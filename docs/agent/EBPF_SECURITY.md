# eBPF runtime security and Zero Trust
Use Cilium/Hubble for identity-based network policy and flow visibility, Tetragon for process/file events. Keep AWS VPC CNI unchanged; evaluate chaining compatibility, kernel/BTF, node type, policy limitations and resource overhead before any EKS installation. Local Linux kind lab first, with explicit setup/cleanup; no cloud resources. Default deny with explicit DNS, ingress, service and DB paths; service accounts, least privilege, restricted pod security; DB accounts and TLS separate. Start Tetragon in observe-only mode; no automatic kill or quarantine. Collect Hubble/Tetragon events, normalize timestamps and identifiers, resolve pod UID/container ID to immutable image digest via Kubernetes metadata (handle deleted pods, missing digest, multiarch mapping). Join with scan findings; co-occurrence is a risk signal, not proof of exploitation. Deduplicate, redact sensitive arguments, limit retention and access. Prometheus metrics with bounded cardinality, Loki logs and Grafana dashboards. Test allowed/denied flows, benign process events, unsigned admission rejection, stale feed and expired exception rejection, missing metadata and duplicate events. If kernel or cluster unavailable, use fixtures and mark live tests NOT RUN. Document mTLS and workload identity as separate controls; do not claim eBPF alone provides Zero Trust.

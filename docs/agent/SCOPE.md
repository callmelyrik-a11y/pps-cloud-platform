# MVP scope (proposed implementation baseline)
FastAPI organization-service and notice-service, Python 3.12, SQLAlchemy 2, Alembic, MySQL 8 locally / Aurora MySQL target, Redis, S3 adapter with local fake, React + TypeScript + Vite static frontend, pytest/HTTPX and Playwright. Pin dependencies and lockfiles. Existing README confirms React/FastAPI/Aurora/Redis. No Spring migration.
Implement organization list/detail/create/update, ACTIVE/INACTIVE; notice list/detail/create/update/publish/close/cancel; attachment presign/confirm/download/remove with validation; append-only audit. Separate organization_db and notice_db credentials. Logical organization ID via internal REST, no cross-schema FK; attachment and audit physical FK to notice. Decimal(18,2) as JSON string; UTC; optimistic version conflict 409; audit in same writer transaction; DRAFT -> PUBLISHED -> CLOSED or DRAFT/PUBLISHED -> CANCELLED. Redis cache for reads with invalidation after commit, graceful fallback. Pagination and request IDs. Local synthetic data only. No bid submission, contract, auth-service, SQS or payment in phase 1. Mutation APIs must not be publicly exposed until authentication/authorization approved; local demo only or restricted port-forward. Do not claim production readiness.
Infrastructure discrepancy: current infra/terraform/environments/dev/main.tf defines branch VPC 172.20.0.0/16 and shared EKS peering; do not assume old design CIDR or deployed endpoints. Inspect all actual Terraform and Kubernetes files before preparing manifests. Existing infra workflow can apply on main infra changes; do not touch it.
